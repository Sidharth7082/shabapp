# Release & update protocol

This section exists so that **no future agent, and no future session, forgets how updates work**.
It is a product requirement, not a convenience.

## The rule

Every build that leaves a developer machine must be published with:

```bash
npm run release -- --patch --notes "Fixed: ..." --notes "New: ..."
# or
npm run release -- --minor --notes-file release-notes.md
```

`scripts/release.mjs` performs the whole release atomically:

1. Bumps `package.json` (and `package-lock.json`) to the new version.
2. Writes `public/update.json` (version, release date, notes, APK URL, release URL).
3. Builds the web bundle, syncs Capacitor and assembles the debug APK.
4. Creates/uploads the APK in the public, source-free release repository
   `Sidharth7082/shabapp-releases`.
5. Publishes the new `update.json` to that repository’s `main` branch.
6. Appends a dated entry to §10 Changelog, bumps `Last updated`, and commits/pushes
   (`chore(release): vX`) so `PLAN.md` always matches what shipped.

**Never hand-publish an APK, never edit `public/update.json` by hand, and never bump the
version without the manifest.** CI fails if `package.json` and `public/update.json` disagree.

## What the installed app does

- On **every launch**, `UpdatePrompt` (mounted in `src/main.tsx`) reads the manifest through
  GitHub’s contents API (uncached, immediate after a release) and falls back to
  `https://raw.githubusercontent.com/Sidharth7082/shabapp-releases/main/update.json`
  (override either with `VITE_UPDATE_URL`).
- If the manifest version is newer, a branded **“New version available”** sheet opens with
  the release notes and two actions: **Download update** (opens the APK in a Custom Tab) and
  **Not now** (remembers that version; the next release prompts again). The check also re-runs
  when the app returns to the foreground after 15 minutes.
- **About → Check for updates** rechecks on demand and reports “You are on the latest version”
  or opens the same sheet.
- Offline launches are unaffected: the check times out silently and the app keeps working.
- Cold-start check takes a few seconds (network + WebView warm-up); the sheet appears as soon as
  the manifest resolves, which was verified on a Pixel 6 emulator.
- **Native builds do not cache assets.** `npm run android:apk` builds with `CAPACITOR=true`, which
  emits a self-destroying service worker and clears any old PWA cache on launch. Without this, an
  APK update could keep serving the previous JavaScript (this happened once and was fixed).

## Public channel

- Manifest: `https://raw.githubusercontent.com/Sidharth7082/shabapp-releases/main/update.json`
  (CORS `*`).
- APK: release asset in `shabapp-releases`; that repository contains **binaries and the
  manifest only** — application source stays in the private repo.
- The website/deployment may also serve `public/update.json`, which is generated by the same
  release step and kept in sync by CI.

## If the manifest host must change

Set `VITE_UPDATE_URL` at build time (for example to Supabase storage) and update §6 of this
plan. The app logic does not change.
